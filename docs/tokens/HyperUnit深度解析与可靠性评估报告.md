## 一、协议背景与运作机制

### 1. 架构定位
Hyperliquid 原生 L1（HyperCore / HyperEVM）本身不具备对 Bitcoin、Solana、Zcash 等非 EVM / 异构公链的原生验证能力。HyperUnit 充当跨链结算中继：
- **充值锁定 (Deposit)**：用户向 HyperUnit 在原生链分配的专属金库地址转账，达到确认数后，协议在 HyperCore 上 1:1 铸造 HIP-1 映射代币（如 `UZEC`、`UBTC`）。
- **赎回销毁 (Redeem)**：用户在 Hyperliquid 上发起提现请求，HIP-1 映射代币在 HyperCore 上被实时销毁（Burn），原生链金库向目标地址转出对应资产。

```
 ┌─────────────────┐       充值锁定 (Deposit)       ┌────────────────────────┐
 │ 原生区块链      │ ─────────────────────────────► │ HyperUnit 跨链托管金库 │
 │ (BTC/ZEC/SOL等) │ ◄───────────────────────────── │ (MPC/TSS 守护者网络)   │
 └─────────────────┘       赎回销毁 (Redeem)        └───────────┬────────────┘
                                                                │ 1:1 动态铸造/销毁
                                                                ▼
                                                    ┌────────────────────────┐
                                                    │ Hyperliquid L1 现货    │
                                                    │ (HIP-1: UBTC/UZEC/@272)│
                                                    └────────────────────────┘
```

### 2. 守护者网络 (Guardian Network)
- **多方计算 (MPC) 与门限签名 (TSS)**：
  HyperUnit 的金库私钥被分割为多份私钥分片，由多位独立的守护者节点（Guardians）共同管理。任何跨链出金操作必须达到预设的门限阈值（$m$-of-$n$）联合签名后方可生效，杜绝了单一私钥被盗即掏空金库的单点故障。
- **手续费模型**：
  - 用户充提跨链服务费。
  - 在 Hyperliquid 现货盘口享有 100% 部署者手续费分成（`deployerTradingFeeShare: 1.0`），以此支撑守护者节点网络和做市流动性。
